Conceptos esenciales de diseño

A.C.I.D. 
Propiedades de las transacciones dentro de un microservicio 
● Atomicity: son una unidad indivisible. Se hace todo o nada. ● Consistency: llevan a la base de un estado consistente a otro ● Isolation: transacciones concurrentes llevan al mismo estado que en  secuencia. 
● Durability: una vez que se comitean quedan, no se pierden. 
B.A.S.E. 
Se dan en transacciones que involucran varios microservicios ● Basically Available – los datos están disponibles la mayor parte del tiempo 
● Soft state – el estado puede cambiar en el tiempo mientras que se logra la  consistencia.  
● Eventual Consistency – si le damos tiempo el sistema va a llegar a un estado  de consistencia. La consistencia de los datos no es inmediata.

Contexto delimitado Bounded Context
Bounded Context 
• Bounded context (contexto delimitado) 
• Es una frontera semántica de uno o más subdominios del negocio 
• Dentro del BD, los expertos del dominio y los desarrolladores entienden lo  mismo (lenguaje ubicuo) 
• Dentro del BC cada elemento del modelo tiene un sentido y semántica  especifica (cohesión) 
• Oculta complejidad y provee funcionalidad a otras partes del sistema  (ocultamiento de información) 
• Ej - Carrera vs. Producto, Estudiante vs Cliente
Subdominios vs Bounded context 
• Subdominios  
• Espacio: problema 
• Se identifican analizando el dominio del negocio • Sirven para entender el funcionamiento del negocio 
• Definen un conjunto de casos de usos, entidades y  datos utilizados
Subdominios vs Bounded context 
•Bounded context 
• Espacio: solución 
• Es resultado del diseño 
• Definen un modelo y sus elementos 
• Implementa los casos de uso definidos para el/los  subdominios que abarca el BC 
• En general para un subdominio puede haber uno o más  bounded contexts 
• Un equipo es dueño de uno o más BCs

Diseño táctico
Diseño táctico 
• Value object 
• Es un objeto que se puede identificar por la composición de  sus calores (estado) 
• Ej,. fechas, colores, números de teléfono, Nombres.  • Son inmutables
Diseño táctico 
• Entities 
• Representan objectos del dominio  
• Requieren un atributo de identificación 
• Implementan la lógica del dominio 
• Todos los cambios al estado del agregado se realizan en una  operación atómica (transacción) 
• Persona, estudiante, curso, etc.  
• Se utilizan en el contexto de los Agregados
Diseño táctico 
• Agregado 
• Son elementos del dominio  
• Requieren un atributo de identificación 
• Agrupan una o más entidades y value objects 
• Se manejan como un elemento único  
• Tienen lógica del dominio 
• Se manejan mediante una interfaz perteneciente al Aggregate Root • Maneja la integridad de sus elementos  
• Todos los cambios al estado del agregado se realizan en una  operación atómica (transacción ACID) 
• EJ: Factura, Pedido, Curso
